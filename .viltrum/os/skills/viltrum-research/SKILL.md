# Investigación Viltrum · D21

Para cubrir la etapa completa lee `departments/D21-research/sops/delivery.md`;
registra outputs y handoff con `core/orchestration.md`.

Activa esta skill antes de construir una capacidad o incorporar un repositorio. Lee `departments/D21-research/AGENTS.md`, `core/doctrine/buy-vs-build.md` y `templates/research-dossier.md`.

1. Reescribe el pedido como capacidad y restricciones medibles, sin partir de una marca o repositorio elegido.
2. Busca en cuatro frentes: capacidad ya existente en el proyecto/Viltrum, solución oficial o del proveedor, proyecto abierto y construcción propia. Evalúa al menos tres candidatos o explica por qué hay menos.
3. Verifica en fuentes primarias licencia, versión o commit, actividad, APIs, seguridad, mantenimiento, costo total y portabilidad. Usa web para información vigente y `viltrum repo-inventory`/`repo-query` sobre la copia clonada cuando el candidato tenga código relevante. Context7 sirve para documentación de librerías, no para confirmar licencia o seguridad.
4. Usa la puntuación y umbrales del método D21. Distingue hecho verificado, inferencia y dato desconocido. Para puntajes intermedios define una prueba acotada con criterio de éxito.
5. Selecciona estrategia E1–E5, adaptador/contrato requerido, riesgos y plan de salida. No instales en un proyecto real durante la investigación.
6. Entrega expediente con enlaces y fecha a D03; involucra D12 antes de reutilizar código o dependencia.

**Salida verificable:** comparación reproducible, procedencia, licencia, puntuación, decisión, prueba pendiente si aplica, estrategia de adopción y plan de salida.
